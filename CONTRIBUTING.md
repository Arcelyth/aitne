# Contributing to Aitne

Since this project is entirely driven by the community and is currently in its early stages, any form of bug reports and pull requests are welcome as long as they can improve the project. Here are some suggestions for those who wish to contribute.

## Reporting Bugs

Before creating an issue, search existing open and closed issues to avoid duplicates. When opening a bug report, you can include:
- A clear, descriptive title.
- Steps to reproduce the behavior.
- Expected vs. actual behavior.
- Environment details (OS, moon version, target engine/browser).

## Proposing Features & API Changes

If you want to introduce new features, refactor core mechanics, or modify current APIs, please open a GitHub Issue or Discussion first:
- Explain the specific problem or use case your feature addresses.
- Outline your proposed API design and how it impacts developer experience (DX).

## About AI

Aitne is not a "vibe coding" project, nor will it ever become one. We prioritize code comprehension, architectural discipline, and maintainable design over unverified code generation.

Given MoonBit's focus on AI tooling and the prevalence of AI assistance in the ecosystem, AI-generated code is not banned, provided you use AI strictly as an auxiliary tool.

When contributing code developed with AI assistance, adhere to the following rules:
- Full Ownership: You must completely understand, explain, and take full responsibility for every line of code you submit. "The AI generated it this way" is not an acceptable rationale during code review.
- Short & Explicit Modifications: PRs should be tightly scoped, focused, and minimal.
- No Massive AI Diffs: Unfocused PRs or one-off massive refactors featuring thousands of lines of generated diffs will be rejected without review. Keep changes concise and easy to audit.
